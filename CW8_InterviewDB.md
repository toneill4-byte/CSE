# Project: Problem Solving with an Interview Database App

**Grade Level:** 9th Grade  
**Duration:** 6–8 Class Periods  
**End Product:** A functional Interview Database app that allows users to record, save, and manage interview responses.

---

## 🎯 Learning Objectives
By the end of this project, students will apply critical problem-solving skills and collaborative strategies to build an interview database app that records and stores user responses. Students will implement core programming concepts—including sequencing, selection, iteration, and abstraction—within a user-centered design framework.

### Key Performance Objectives
* Develop interview questions and design an interface for displaying questions and recording responses.
* Implement variables, loops, and conditional statements to automate question display and data storage.
* Analyze user needs to ensure functional and user-centered app design.
* Evaluate and troubleshoot code for accuracy, functionality, and user experience.

---

## 💡 Warm-Up
> *"Have you ever been in a situation where you needed to remember multiple details? How could technology help?"*

---

## 🛠️ Project Roadmap

1. **Introduction & Features:** Review project specifications; brainstorm UI layouts and data storage strategies.
2. **Design Phase:** Draft wireframes, plan data structures, and get instructor approval on overall app flow.
3. **Coding Phase:** Initialize variables, build input/output logic, and implement loops for cycling questions and saving input.
4. **Testing & Debugging:** Iteratively test features, conduct peer reviews, and fix logical or visual bugs.
5. **Presentation & Feedback:** Showcase completed apps, justify design choices, and swap constructive peer reviews.

---

## ⚠️ Key Misconceptions & Solutions
* **Uncontrolled Loops:** Loops do not run indefinitely; they require explicit exit conditions. Trace loop execution with pseudocode prior to block implementation.
* **Session Persistence:** App state clears on restart unless stored in persistent storage (e.g., local database components). 
* **Variable Assignment:** Variables do not automatically update when referenced values change; they must be explicitly re-assigned inside code blocks.

---

## 🤝 Collaboration Strategies
* **Pair Programming:** Work in driver/navigator pairs during complex logic setup to catch errors early.
* **Peer Reviews:** Exchange projects midway to test usability and catch edge-case bugs.
* **Group Problem-Solving:** Participate in class debriefs to troubleshoot shared coding challenges.

---

## ❓ Depth of Knowledge (DOK) Questions
1. What benefits do loops provide in managing repetitive tasks?
2. How does designing for an external user change your overall approach to programming?
3. In what ways could data from this app be securely stored to respect user privacy?
4. What strategies could you use to effectively debug a program containing multiple interdependent functions?
